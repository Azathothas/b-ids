# Publication review - 2026-09-05

## Scope

This review covers architecture, Rust code, scripts, documentation, workflows,
branch data, release behavior, portability, and repository maintenance before
the initial public release.

The repository was reconciled against `Azathothas/TEMPLATE` at commit
`620616638320147aa2465b304c1240b20eb2d097`. Project-specific capture,
validation, and publication checks were retained where they were stricter than
the generic template.

## Material findings and resolutions

| finding | resolution |
| --- | --- |
| unreadable `corpus/v1/latest.json` became an empty package-pointer set | publication now returns the filesystem error |
| trust extraction treated malformed extension data as absent | absence is skipped; malformed input stops the batch |
| reference import discarded directory-entry failures | entry failures now stop import and name the directory |
| capture continued after failing to install a socket read timeout | the failure is recorded and capture stops before an unbounded read |
| the pre-publication data check required the remote branch to equal unpublished generated bytes | pending derived updates are allowed only when no path disappears and every immutable artefact remains byte-identical |
| generation scripts assumed Cargo always wrote to `target/` | shell and PowerShell twins honor `CARGO_TARGET_DIR` |
| workflow pin validation depended on GNU-awk interval syntax and unstripped CR bytes | it now uses portable length/hex checks and normalizes line endings |
| PowerShell Node discovery produced an invalid combined path when two launchers resolved | it deterministically selects the first command |
| `v0.0.1` could not trigger or pass the dated corpus-release parser | a one-time, immutable bootstrap release rule is tested separately; later releases retain `v1.YYYY.MM.DD.N` validation |
| current documentation carried volatile counts, stale paths, pre-release narrative, and contradictory security prose | current docs now use generated pointers, direct result links, concise operating rules, and a current security policy |
| all 107 completed implementation entries remained under root `TODO/` | completion was verified before moving the record to `docs/history/todo/` |
| dependency automation covered Actions but not Cargo | weekly grouped Actions and Cargo updates were added |
| the public secret sweep classified a pinned OCI SHA-256 digest as a credential | the twins exclude only canonical `@sha256:<64 lowercase hex>` references; an unlabeled 64-hex mutation still fails |
| the Windows doctor aborted on an inaccessible executable candidate | fallback discovery now skips inaccessible candidates and continues |

not obsolete plans.

## Repository maintenance

GitHub read-back confirmed private vulnerability reporting and vulnerability
alerts enabled, automated security fixes enabled and unpaused, and zero open
secret-scanning alerts. After the first push, dependency-graph indexing found
202 Dependabot alerts, all in immutable third-party manifests under
`references/`; no first-party manifest is affected. Those imported trees are
not installed or executed by this project and remain byte- and path-exact for
provenance. Their final `not used` classification requires an explicit
repository-owner decision. The `dependencies` label exists for the weekly
grouped update configuration.

`main` requires current `gate (ubuntu)` and `gate (windows)` checks with strict
status-check freshness. It requires linear history and conversation resolution,
disables force pushes and deletion, and retains administrator bypass so
legitimate repository automation is not blocked.
